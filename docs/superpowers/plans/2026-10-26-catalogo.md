# Catálogo Bourscheid — plano de implementação

**Objetivo:** implementar a primeira SPA funcional descrita em `AGENTS.md`, usando as fotos reais de `raw`, pronta para build na Vercel.
**Arquitetura:** React + TypeScript + Vite; Framer Motion; repositório IndexedDB substituível por API. Curadoria local explicitamente identificada, sem simular autenticação de servidor.
**Execução:** usuário autorizou iniciar diretamente e orientar durante o trabalho. Implementação no workspace fornecido; `.git` é somente leitura neste ambiente.

## Restrições e decisões
- Verde #0B1911, dourado #D4AF37, vermelho #D9232E. Tipografia Cormorant Garamond e Inter.
- Spring stiffness 300 / damping 30, com respeito a reduced-motion.
- Status como enum: disponível, reservado, vendido (booleano não representa os três estados pedidos).
- Dois exemplares iniciais identificados por código; espécie/idade/medidas não inferidas das fotos. Preço sob consulta.
- Fotos preservadas em `raw`; cópias públicas em `public/images`.
- Número WhatsApp não fornecido: configuração obrigatória antes de abrir contato.
- Edições locais não são publicadas para outros visitantes. Backend/autenticação ficam para etapa posterior.

## Tarefas
- [x] Base Vite/TS e configuração Vercel, tipos e validação de backup, testes de mensagens e persistência.
- [x] Catálogo responsivo, busca/filtros, hero atmosférico e modal de galeria acessível.
- [x] Curadoria inline, CRUD, upload/URLs, capa/tags, configurações e import/export.

## Foco de revisão
Backup inválido não substitui catálogo; URLs perigosas são recusadas; falha de armazenamento não reporta salvamento; campos desconhecidos não são inventados; compartilhamento indisponível tem fallback.

## Verificação planejada
`npm test` cobre validação, mensagens, normalização de telefone e persistência com IndexedDB.
`npm run build` cobre TypeScript e bundle. Revisão de teclado, modal, mobile e dados no browser quando runtime disponível.

## Registro
Ambiente inicial: atalhos Node/npm apontam para arquivos ausentes, terminal sem resolução DNS. Testes serão escritos antes da implementação; execução depende de runtime disponível. Sem alegar RED/GREEN se não executados.

Código e README escritos. Domínio: 11 testes passaram. Revisão independente encontrou e confirmou correções de limite de backup, revisão transacional e compartilhamento local.

## Refinamento solicitado — seis pontos

Inputs nativos ocultos e upload acionado por botão.
Migração somente dos dois placeholders intactos para não sobrescrever edições locais. Mantida uma foto real por exemplar, sem fabricar ângulos/alturas/cultivo.
Verificação posterior: build de produção passou; suíte de três arquivos passou (17 casos). Revisão independente: corrigidas sincronização da capa e remoção de zoom ao selecionar escala real. Verificação visual pendente porque servidor retorna listen EPERM neste ambiente.

## Estúdio Virtual
BonsaiStage compartilhado entre card/modal/editor; 3 pedestais SVG, Tokonoma, luz por tema e sombra. Matte Canvas em Worker com 2 trabalhos simultâneos, visibilidade e cache limitado. Inputs Y/zoom/corte/intensidade e original preservado. Novas fotos estimam corte; sementes calibradas em 22%.
Verificação: 27 testes + build passaram. Teste real dos dois JPEGs revelou confusão tronco/parede; adicionada proteção conservadora às fontes conhecidas. Recorte é heurístico e seus limites estão documentados. Revisão corrigiu upload com estúdio desativado e concorrência excessiva. Sem validação interativa de browser.
